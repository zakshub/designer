# Anti-Monotony Audit

Purpose: stop unrelated products from converging on Sentinel's own recurring aesthetic habits.

This is not a demand for novelty at all costs. Reuse is valid when the product context justifies it. The audit asks for evidence before repetition.

## Pre-approval comparison

Compare the candidate direction against recent unrelated projects across these dimensions:

### Color
- canvas/background family;
- primary brand hue;
- accent hue;
- neutral temperature;
- semantic state palette;
- light/dark balance.

### Typography
- serif/sans/mono roles;
- display/body pairing;
- scale ratios;
- numeral treatment;
- uppercase micro-label patterns.

### Composition
- sidebar vs top navigation;
- card-grid dependence;
- hero/dashboard structure;
- asymmetry;
- whitespace rhythm;
- information density.

### Surfaces
- border usage;
- shadow/elevation;
- glass/translucency;
- corner-radius family;
- panel tone relationships.

### Brand expression
- photography;
- illustration;
- 3D;
- data visualization;
- decorative geometry;
- icon family;
- motion language.

### Interaction
- tabs;
- drawers;
- command palettes;
- feeds;
- notification models;
- progressive disclosure;
- approval patterns.

## Repetition trigger

Flag a candidate when several unrelated choices repeat together without a product reason, for example:

- warm ivory canvas;
- near-black sidebar;
- muted cards;
- green accent;
- large editorial heading;
- rounded 16–24 px cards;
- identical spacing rhythm.

Any one of these may be appropriate. The concern is an unexplained bundle becoming a default house style.

## Required response to a flag

Do not simply change the accent hex.

Generate at least two materially different alternatives by changing structural axes such as:
- navigation model;
- density;
- typographic voice;
- neutral temperature;
- surface hierarchy;
- image/art direction;
- spatial composition;
- motion character.

Then compare tradeoffs against the original direction.

## Similarity note

For each production-ready direction, record:
- closest prior project visually;
- similarities;
- differences;
- why remaining similarities are justified by product requirements.

## Category repetition vs product repetition

Some patterns recur because they solve a task well. Preserve those mechanisms where useful. The audit targets accidental stylistic repetition, not valid UX conventions.

Examples:
- A table may recur across finance and admin products because tabular comparison is appropriate.
- A warm cream background should not recur across finance, fashion, portfolio and tax products merely because it feels premium.

## Reference-diversity gate

Before final styling, references should include more than one origin group. Do not let a single inspiration source dominate the direction.

Recommended mix:
- 2–4 shipped-product references;
- 1–2 design-system/platform references;
- 1–3 brand/identity case studies when brand expression matters;
- research/expert evidence when making behavioral or perceptual claims.

## Final question

If the logo and product name were removed, would this screen be easily mistaken for an unrelated recent Sentinel project?

If yes, investigate whether the similarity is justified. If not justified, redesign before approval.
